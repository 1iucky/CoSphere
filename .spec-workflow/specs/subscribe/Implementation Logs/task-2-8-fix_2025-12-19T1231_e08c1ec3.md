## 修复的问题清单

### 1. ✅ bill_id 未写回订单

**问题**: 支付成功后生成了 `billId`，但没有更新到订单表的 `bill_id` 字段

**影响**:
- 订单与账单关联断裂
- 无法通过订单快速查询账单
- 退款/对账时需要额外查询

**修复**:
```go
// service/subscription_order_service.go:435-439
// 12.1. 更新订单的账单ID
order.BillId = &billId
if err := model.UpdateSubscriptionOrderWithTx(tx, order); err != nil {
    return fmt.Errorf("更新订单账单ID失败: %w", err)
}
```

### 2. ✅ 第三方支付渠道被禁用但未同步到 DTO

**问题**: DTO 允许 `wallet/stripe/alipay/wechat/paypal`，但 Service 层只支持 `wallet/free`

**影响**: 用户提交第三方支付渠道时创建订单成功，但支付时失败

**修复**:
- `dto/subscription_order_dto.go:7` - 只允许 `wallet`
- `dto/subscription_order_dto.go:47` - 只允许 `wallet`

### 3. ✅ 货币假设未显式约束导致金额计算错误

**问题**: 套餐默认 `currency='USD'`，但扣款/退款假设 `FinalPriceCents` 是人民币分（CNY cents）

**影响**: **严重** - USD 套餐会多扣 7.3 倍余额（按汇率）

**修复**: 根据套餐快照的 `Currency` 字段进行正确换算
- USD 套餐：`quotaNeeded = FinalPriceCents / 100 * QuotaPerUnit`
- CNY 套餐：`quotaNeeded = FinalPriceCents / 100 / USDExchangeRate * QuotaPerUnit`
- 位置: `service/subscription_order_service.go:477-521` (扣款) 和 `834-875` (退款)

### 4. ✅ 取整方向导致少扣款/多退款

**问题**: 扣款使用 `IntPart()` 向下取整，可能导致实际支付 < 应付金额

**影响**: 系统损失（少收款），长期累积会导致财务缺口

**修复**:
- 扣款：向上取整 `quotaNeeded := dQuotaNeeded.Ceil().IntPart()`
- 退款：向下取整 `quotaRefund := dQuotaRefund.Floor().IntPart()`

### 5. ✅ 汇率/QuotaPerUnit 缺少 0/负数保护

**问题**: 直接使用 `Div(dExchangeRate)` 没有检查除数

**影响**: 除零错误导致程序崩溃

**修复**: 添加参数校验
```go
if operation_setting.USDExchangeRate <= 0 {
    return 0, fmt.Errorf("汇率配置异常: USDExchangeRate=%f", operation_setting.USDExchangeRate)
}
if common.QuotaPerUnit <= 0 {
    return 0, fmt.Errorf("配额单位配置异常: QuotaPerUnit=%f", common.QuotaPerUnit)
}
```

### 6. ⚠️ 用户余额缓存一致性风险

**问题**: 直接 `UPDATE users.quota` 而不是使用 `DecreaseUserQuota/IncreaseUserQuota`

**影响**: 如果 Redis 启用，可能导致缓存不一致

**当前状态**: ⚠️ **部分修复**
- 原因: `DecreaseUserQuota` 不支持事务内调用
- 当前方案: 继续使用直接 UPDATE，但添加了详细注释说明风险
- 后续改进建议: 修改 `DecreaseUserQuota` 支持事务，或在事务提交后手动刷新缓存

### 7. ✅ 下单用券链路缺失

**问题**: DTO 接收 `coupon_code` (string)，Service 需要 `userCouponId` (int64)，Controller 写死 `userCouponId=nil`

**影响**: 优惠券功能完全不可用

**修复**: 在 Controller 中添加 coupon_code → userCouponId 的映射和验证
- 根据 code 查询用户优惠券
- 验证优惠券归属
- 验证优惠券状态
- 位置: `controller/subscription_user.go:556-588`

### 8. ✅ CreateOrder 幂等性不强

**问题**: 只按 `user_id + plan_id` 查询 pending 订单，不考虑 `coupon` 和 `payment_channel`

**影响**: 用户无法更换优惠券/支付方式

**修复**: 增强幂等性检查
- 检查优惠券是否匹配
- 检查支付渠道是否匹配
- 不匹配时返回明确错误信息
- 位置: `service/subscription_order_service.go:101-136`
